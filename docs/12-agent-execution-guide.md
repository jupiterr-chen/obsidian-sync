# 长任务执行指导书

## 权威顺序

用户最新指令与全局安全规则 > 根AGENTS.md > 本任务书/11整合任务书 > 07任务计划与08验收 > 其他设计 > docs/legacy历史说明。用户已经决定以obsidian-sync为主工程，覆盖01、07及ADR0001早期“独立新服务”的仓库假设；现有library能力仍保留。

本指南用于后续agent，自行推进可安全完成的工作，不要求用户逐阶段回答“继续”。当前文档编写agent没有调用其他agent执行实现。

## 工作台账

开始时创建 `docs/progress/task-status.md`（不含敏感基础设施），字段：任务ID、状态、负责人、依赖、变更commit、验收报告、阻塞条件、下一动作。初始M0=todo，P0=accepted（设计范围），P1-P6=todo。明确区分源码实现、离线验证、全量数据验收、生产部署四种完成度。

每个阶段报告放 `docs/progress/<stage>-report.md`，真实数据、机器路径、账单及凭据相关证据存忽略的 `runtime/evidence/`，公开报告只放聚合指标。会话检查点放 `docs/progress/HANDOFF.md`：当前commit、已完成任务、失败测试、启动中的进程、下一步和阻塞，不能存token/key。

## 每个任务的闭环

1. 读相关模块和任务验收，不全盘无目的阅读；记录当前状态。
2. 以最小兼容变更实施，保护现有用户修改。
3. 执行有意义的测试：原有回归+任务场景，不以空stub/镜像测试代替功能。
4. 检查实际diff、数据路径、权限、版本、失败恢复和成本，不接受执行摘要作为唯一证据。
5. 修正失败；同一失败连续3轮先分析根因，最多5轮无进展后标记BLOCKED并继续独立任务，不无限重试。
6. 更新台账和报告，提交小而完整的变更。提交信息引用任务ID。
7. 依赖满足时自动启动下一任务。未满足的任务留明确阻塞，不通过降低验收阈值继续上线。

单一agent工作时自审需明确标记self-reviewed。平台支持多agent且用户粘贴了14提示词中的授权时，可分配独立范围并由主agent实查diff/运行测试；同一目录单writer，复核agent只读或使用独立工作区。agent之间不能用摘要互相“盖章”。

## 默认授权与自动推进范围

后续提示词授权本地主仓库内源码/文档/合成测试、正常依赖安装、保留源目录的复制、提交及向唯一指定远端正常推送。可以生成部署配置和离线演练工具，不因此获得生产主机改动许可。

不执行递归删除/移动/权限变更；不打印或复制密钥；不修改两份原始归档/导出器；不自动合并或覆盖人工研究；不force-push；不操作其他远端。无需为普通实现选择逐次提问。

真实生产部署、持久服务切换、真实Vault写回、云端资料外发与计费模型调用需要用户提供可复用的明确范围、访问方式和预算。在没有这些条件时完成独立工作后统一列出最少缺项；不为了“无人介入”猜账号、花钱或重启生产。

## 检查点与自动续跑

长任务不意味着单次会话无限持续。agent有持久任务/原生自动恢复能力时，使用其能力和HANDOFF继续；普通聊天agent结束后不能自我唤醒。可生成项目级resume命令或调度任务草案，未授权不擅自创建生产调度。

每20-30分钟或阶段结束写检查点；用户在场时至少每60秒给一条简短有实质内容进度，不必等催促。进入长时间工具调用前说明目标；正常运行不反复请求继续。

## 最终交付

汇总任务状态、提交、测试、真实/合成数据覆盖、全量token实测、模型成本、上线状态及阻塞项。不能把P0/M0或离线全部通过说成P6已完成。剩余工作提供准确resume起点。
