# 分阶段交付、任务划分与依赖

当前只交付 P0。P1-P6 均为待实施，不把计划当作完成记录。负责人是角色分工，未默认启动并行代理；每个任务由实施人员认领后记录实际负责人、提交和验收报告。

## 阶段与交付门禁

|阶段|目标|前置|交付与退出条件|
|---|---|---|---|
|P0 设计基线|设计、框架、契约、预算|当前清单|文档相互一致、合成契约有效、Git 已同步|
|P1 样本与数据基础|版本登记、只读接入、测量|P0、library 可达|30份样本、真实页数/Token报告、版本幂等与权限验证|
|P2 正文与 OCR|可定位正文、HTML、表格|P1|盲测通过、低质量隔离、完整派生产物|
|P3 全文服务|关键词、查询接口、影子全量回填|P2|搜索指标通过、原文可打开、重复运行无重复、人工区零覆盖|
|P4 语义与分析|混合检索、带证据草稿|P3、供应商与预算选定|离线问答评测通过、用量可核对、引用验证|
|P5 长期记忆|假设、反证、版本与写回|P4|修订/拒绝/失效场景通过、历史决策不变|
|P6 稳态自动化|调度、备份、监测、应用接入|P3起可并行筹备|连续7天稳定、恢复演练及客户端验收|

P3 可独立作为有用产品交付，不必等 LLM 和记忆功能。P4/P5 不在用户确认供应商前发起全量模型处理。

## 实施顺序与时间估计

优先 P1 接口核对与样本，避免先选模型再发现正文不可靠。P2 可以按格式划分，但同一运行目录只有一个索引发布者。首次人工成本主要是样本标注与表格验证。没有服务端硬件和页数，当前不承诺处理耗时或开发日数；P1 结束后以页/秒、OCR吞吐、索引吞吐和人力重新估工。

## 完成记录规范

每个任务记录状态（todo/in_progress/blocked/accepted）、负责人、提交 SHA、测试命令、样本版本、测量环境、指标值、失败样本及已知限制。只有验收证据符合门禁才能 accepted；不可凭模型总结验收。
