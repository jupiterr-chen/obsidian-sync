# 接入、正文处理与检索

## 增量流水线

1. 每小时读取 library 清单或变化游标，另设日级一致性对账。
2. 文件变化后等来源 ready 且哈希/大小稳定；下载临时对象后验证，不依赖 mtime 判定版本。
3. 登记源版本和唯一任务键：document+source_version+stage+configuration_digest。
4. 提取文字层与布局；按页/区域评估质量，必要时 OCR。
5. 规范化段落与表格，保留原始文字与规范化映射。
6. 质量评估、分块、索引 staging generation。
7. 完整性检查后原子发布；失败保留旧 active generation。
8. 发出 versioned change event，更新生成状态或形成研究复核候选。

## 格式策略

PDF：先提取文字层，检查每页字符密度、乱码/替换字符、可见内容覆盖、多栏顺序、重复文本。稀疏页不一定是扫描件，封面/图表页单独分类。OCR 仅补充低质量区域/页面，合并时去重；不能只凭字数多判定质量好。

图片：本地 OCR 与区域定位，图表数值解析独立评估。没有读出的关键数字标记未知。

HTML：DOM 解析去导航、脚本与样式，保留章节、段落和完整表格。SEC inline XBRL 允许独立事实适配器；companyfacts 等结构化来源保存 accession、期间、单位与重述身份，不能混作普通文本结果。HTML 本地快照净化后展示。

纯文本：识别编码、保留字符定位。所有来源设置 MIME、大小、页数、耗时限制；损坏文件进入隔离状态，正常资料继续处理。

## 候选工具测评

文字 PDF 可比较 PyMuPDF、pdfplumber；复杂布局可比较 Docling；本地中英文 OCR 可比较 PaddleOCR/Tesseract 类引擎。均是候选，不表示已安装或选定。OCR 与布局模型属于机器学习，但不必调用生成式 LLM 或按 Token 付费。依赖许可证、Windows/服务器兼容和离线能力纳入选型记录。

## 分块

以章节、段落和表格为语义边界，避免跨公司、跨章节拼接。目标窗口初定 800-1500 tokens，必要时少量重叠；参数通过样本调优并版本化。表格保留结构对象，搜索文本为带表头的投影；投影不能作为唯一财务计算数据。长表按行组分块并复制必要表头，记录重复带来的 embedding 成本。

## 检索

P3：关键词与结构化筛选；中文分词+原文短词回退，中英文混排、股票代码、两字词（毛利）、百分数、缩写必须覆盖。原文显示偏移通过映射恢复，不能把分词后位置当原文位置。以 BM25 类排序为起点，不直接混用 metadata 与全文分数。

P4：关键词和 embedding 并行召回，按 rank fusion 合并，可选 reranker。精确代码和数字查询保留关键词优先通道。所有召回先施加权限、集合和 as_of 过滤。检索结果包含匹配原文、上下文、日期、位置、提取质量和固定引用。

## 质量基准

先选 30 份分层样本，覆盖中文多栏、英文 PDF、扫描、混合 PDF、复杂表格、HTML、图片、文本；类别交叉，不要求每类占据独立数量。人工标注段落顺序、关键数值、位置和问答证据。20 份用于选择/调优，10 份盲测；不得用调优集代替最终验收。

低质量文档可进入搜索但必须有明显 quality 状态；涉及低置信度数值的自动计算默认拒绝，等待复核。抽样比率、阈值和失败类别写入质量报告。
