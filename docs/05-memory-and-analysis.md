# 研究分析、长期记忆与应用接入

## 三种记忆

证据记忆：原文、提取正文、事实和位置，不允许生成模型改写后替代来源。

研究记忆：公司画像、主题、研究假设、支持证据、反证、适用日期、确认状态。每条 claim 保存 revision、author/model、prompt_version、evidence_refs、reviewer、reviewed_at、status。状态为 proposed/accepted/challenged/superseded/rejected；过时不代表原历史应删除。

决策记忆：资金配置/研发选择的时间、目的、约束、当时证据与假设版本、触发条件和事后复盘。历史决策引用冻结；新的研究记忆不能改写旧决策理由。

## LLM 分析边界

模型读取查询召回的证据，输出带 block_id 的结构化草稿。后处理验证每个引用存在、权限通过、版本固定和引文文本匹配；是否支持结论还需要规则、第二阶段检查或人工抽样，不能由“引用存在”推出结论正确。

优先支持文档摘要、跨期差异、风险与反证提取、公司/主题综述、变化影响建议。精确金额计算使用结构化事实与确定性程序；模型只解释计算结果。缺少证据明确表达未知。文档中的指令、链接和脚本不进入控制权限。

## 增量更新

新源版本 -> 证据差异 -> 受影响 claim 列表 -> 复核候选 -> 可选 LLM 建议 -> 确认 -> 新 revision -> Obsidian 生成成果。大规模自动确认只适用于明确配置、通过验证的客观字段；投资判断默认人工确认。来源日期新不代表观点自动更可靠。

## Obsidian 写回

推荐新增独立 `自动研究候选/`、`证据索引/` 生成区（尚未创建），人工区沿用现有路径。候选记录包含来源、证据、生成日期、模型/提示词版本、质量及待审核状态。确认后可形成研究记录，人工全文编辑不被下一次生成覆盖。

自动写入采用允许路径清单、文件 owner 和前一内容哈希；用户修改或同步冲突时停止覆盖并保留候选。知识服务不自动删除 sync-conflict 文件。

## 应用集成

研发应用：以问题/项目背景调用检索，记录采用的证据集合与研究输出。

资金管理应用：按公司、行业、期间和 as_of 调用；将研究信号与持仓/预算/风控规则分开。保留研究建议产生时间、使用数据版本与人工决定。此工程不实现交易执行，也不把某条 LLM 结论直接作为订单。

通用接入上下文清单：purpose、query、filters、as_of_mode、generation_id、evidence_refs、claim_revisions、result_digest。调用应用持久化这份清单，重放时可找到相同历史依据。

## 为什么不做“全文塞进永久记忆”

原文持续增长，模型上下文有限；摘要会遗漏或失真。永久载体应是可导出的文件与数据库，模型按任务检索，并记录使用的证据。向量缓存可重建，模型会话不承担唯一记忆职责。
