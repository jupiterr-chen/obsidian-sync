# ADR 0003：知识层独立存储与内容寻址快照

状态：已接受，2026-10-01（P1-02 实现）。

## 背景

doc/11 指出：现有原文版本在上游字节被覆盖后 fail-closed（409/conflict），历史证据随之永久不可读；新正文状态与索引也不能写入现有 catalog，避免未经审核的大型迁移损伤第一层。

## 决定

1. **独立知识库** `state/knowledge.sqlite3`（默认路径，可配置）：镜像 `(source, doc_id, version_id)` 身份 + 快照/提取/任务状态。对第一层 catalog 只以 SQLite **只读连接**（`mode=ro`）消费，绝不在知识侧打开写连接，也不迁移其 schema。
2. **内容寻址快照库** `snapshots/<sha256[:2]>/<sha256>`：
   - 快照流程：`hash_file_stable` 稳定性验证 → 打开**同一文件描述符**，流式哈希+复制到临时文件 → 复读临时文件复验哈希 → 原子 rename 到最终路径 → 事务内绑定 `(source, doc_id, version_id) → sha256`。
   - 同 sha256 的 blob 物理共享（跨来源/跨文档），已存在且大小一致视为验证通过；大小不一致报完整性错误，**绝不覆盖**已存在 blob。
   - 上游身份冲突（源哈希 ≠ 版本声明哈希、或不稳定）→ 不快照，任务记 `failed(SourceConflict)`；既有快照不受影响，旧证据仍可读。
3. **任务幂等键** `(source, doc_id, version_id, stage, config_digest)`，库级 UNIQUE 约束 + 确定性摘要；重复注册为 no-op。任务带 attempts/lease_until，中断恢复把过期 running 重置 pending（A03 场景）。
4. **对账策略**：知识侧以每日全量版本枚举幂等 upsert 为完整性依据；library 变更账本（changes）仅作加速线索，不承担完整性责任（其无消费游标/保留承诺，doc/11 已知）。
5. 阶段注册顺序：`snapshot` →（P2 起）`extract` 等后续 stage，仅对 `state=ready` 的版本注册快照任务；catalog 侧 conflict/missing 如实镜像，不触发任务。

## 收益与代价

收益：旧引用绑定固定源版本与快照字节，重提取/上游覆盖不破坏历史证据；知识层故障不影响第一层服务；A02/A03 幂等与恢复由约束+状态机直接保证。

代价：存储翻倍（快照副本 ~1.76GB 量级，服务器部署时评估磁盘）；跨库一致性依赖对账，容忍最长一个调度周期的滞后；快照验证增加读取开销（每版本一次全量读）。

## 回归成本

无第一层行为变更（仅只读消费）。113 项回归继续通过；新增知识层独立测试不进入 library 测试文件。
