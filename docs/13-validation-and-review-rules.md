# 整合与自动执行验证规则

## V0 来源及目标保护

执行前保存源HEAD/工作树状态、目标HEAD/工作树状态；Vault与Tools仅记录安全聚合/允许范围，不将个人文件内容写入公开报告。源工作树不改，复制只读公开tracked文件；发现未提交修改不得丢弃。验证hash不能代替隐私审核。

## V1 复制验收

源路径在明确工程内，目标路径在主仓库内，拒绝..、路径穿越、符号链接逃逸和隐藏Git目录。只复制allowlist公开文件；目标已存在则比较/合并。保存源commit、文件hash、映射manifest。不得复制.env或私人配置。源docs/GIT_DELIVERY的旧42文件描述是历史，不替代实际52跟踪文件审核。

## V2 第一层回归门禁

导入测试先保持原样，运行全部unittest，再增加新模块测试。失败不能通过删测试、弱化断言或屏蔽目录规避。对hash文件服务、HEAD/Range/ETag、目录幂等、小时调度、变更账本、状态脱敏、人工区保护保持原语义。

## V3 新层完整性门禁

08的A00-A22是目标指标。必须区分PASS/FAIL/NOT_RUN/BLOCKED，保留样本与配置版本。引用完整性、权限、人工区保护、财务关键口径属于硬门禁，不能用平均分掩盖重大错误。

## V4 计费及模型门禁

默认generation与embedding关闭，不能把工程agent订阅等同于API账户授权。输入计数、预算、供应商、模型、是否允许外发、重试上限确定后才能运行真实任务。测试mock只能验协议；质量及成本必须实测。OCR本地模型与云端多模态另计。

## V5 Git门禁

主remote必须精确为git@github.com:jupiterr-chen/obsidian-sync.git。检查staged路径、diff --check、凭据/运行资料及文档链接。只提交审阅过的变更，用户改动不得夹带。普通push失败先报告/同步核对；不得force、不随意reset、不得推旧research-kb远端。公开文档避免新增个人机器、私有服务器信息，现有任务书路径仅用于授权范围。

## V6 生产门禁

离线测试通过不代表部署。明确主机、目标目录、现有服务、只读源、运行用户、回滚及备份后，才执行已授权部署。不得docker compose down -v、volume prune、chmod/chown或递归清理。备份恢复在独立测试目录验证，涉及清理的步骤改为保留或等待准确路径批准。

## 停止与继续规则

有危险路径/秘密泄露/源修改风险时立即停止相关动作。来源离线、GPU缺失、供应商未选等局部阻塞不要求整个项目停下；做离线实现、适配、测试和文档。只有所有剩余工作都依赖外部条件时结束，并给HANDOFF及一份合并缺项列表，不声称自动完成。
