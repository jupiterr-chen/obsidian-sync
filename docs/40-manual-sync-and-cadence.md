# 自动接入频率与手动同步

2026-10-07：用户要求说明自动接入与 Obsidian 可见时延，并在现有状态面板增加手动入口。本文件同时记录实现范围和本地验收；本次代码尚未部署生产。

## 当前生产频率

以下数值来自服务器实际配置和 Windows Syncthing 配置，不是产品默认值推断。

|环节|频率/触发方式|到本地可见的含义|
|---|---|---|
|Discord 上游下载/建索引|由上游导出项目负责|仅下载文件但未更新 `index/documents.jsonl`，不会进入本仓库目录；本按钮不触发 Discord 下载|
|资料接入、文档卡片生成|自动任务完成后间隔 3,600 秒检查下一轮|新文件及索引到齐后，等待约 0–60 分钟，加扫描/卡片生成与文件传输耗时；任务异常或正在处理时可能更久|
|知识层增量正文处理|每轮结束后间隔 1,800 秒|历史修复期间暂停；正常修复结束后监督进程恢复。随后依队列执行快照、正文提取、必要页 OCR、索引和正文发布|
|Syncthing 文件变化监听|两端均启用，变化聚合等待 10 秒|文件生成后可直接开始扫描/传输，不需要再等一小时；两端在线、无积压的小文件通常是秒到分钟级，这不是交付时限保证|
|Syncthing 兜底全量扫描|配置 3,600 秒|不是“每小时才同步”；实际扫描间隔会有随机浮动|
|同步状态采集 / 网页刷新|约 20 秒 / 15 秒|面板显示可能稍晚于真实传输完成|

资料卡片与解析正文有各自等待时间。正文还受排队、文档长度、OCR 页数、失败重试和历史修复进度影响，不能用 Syncthing 的 10 秒监听延迟来估算全文可见时间。电脑离线时服务器可继续处理，Windows 重新上线后才接收文件。

Syncthing 行为参见官方 [同步机制](https://docs.syncthing.net/users/syncing.html)。2026-10-07 只读核实服务器及 Windows 的 `research-vault` 均为 `fsWatcherEnabled=true`、`fsWatcherDelayS=10`、`rescanIntervalS=3600`。

## 界面如何用

现有生产状态面板为 `http://192.168.1.150:8765/`。本批发布后会新增：

1. **立即同步资料**：跳过资料目录自动检查的等待，立即读取已配置的来源索引、更新 catalog 和文档卡片。返回后在按钮旁显示正在执行、完成、被已有任务占用或失败。这里的“完成”只代表资料接入/卡片生成完成；Windows 是否收到仍看下方 Syncthing 状态。
2. **打开本机 Syncthing**：打开当前电脑的 `http://127.0.0.1:18384`（已核实的 Windows GUI 地址）。展开 `research-vault` 可使用 Syncthing 自带的“重新扫描”。这只是管理页面入口，本面板不会取得 Syncthing 密钥或直接调用它的写接口；从其他电脑打开时，该电脑也需在此地址运行 Syncthing。
3. 原有 **刷新状态** 保持只读，仅重新读取状态；不会接入资料。

手动资料接入完成后，由现有 Syncthing 文件监听继续传输卡片。它不会替代文件同步，也不会强制 Windows 在线。手动重新扫描作用于按下按钮的那一端；服务器尚未生成的正文，无法通过本地扫描提前获得。

## 实现与冲突防护

- 新增 `POST /api/v1/actions/ingest`，请求体只能是 `{}`。响应 202 表示接受/已有同一请求运行；前端通过原状态接口中的 `manual_ingest` 查看最终结果。429 表示短时间重复触发，等待返回的 `retry_after_seconds`。
- 新控制器只调用已有 `library.ingest.Ingestor`；复用跨进程 `ingest.lock`，不与定时/命令行接入同时写目录。已有接入任务占锁时显示 busy，不冒充成功。
- 同时点击合并到同一请求，结束后按请求开始时间实行 30 秒冷却。手动运行不更改自动调度的下一次检查时间。
- 不调用知识层 worker、OCR、模型、历史批次重建或 Syncthing 写接口；不改源码资料、生产配置、Vault 人工区或权限。知识数据库和其任务队列不由该按钮打开。
- 响应仅返回经过限定的状态、变更数量、请求 ID 和时间；不返回源路径、异常堆栈、正文或凭据。任务结果保留在既有 `ingest_runs` 中；按钮当前请求状态只在进程内，服务重启后看最近入库记录确认结果。
- 沿用现有可信局域网面板的访问边界，没有新增账号系统。写操作检查固定 Origin、Host、同源请求头和 JSON 请求体，拒绝跨站触发、DNS rebinding 和自定义命令/路径。`public_base_url` 应与实际面板地址一致；不要将该面板直接开放公网。
