## 权限与交付流程

本任务授权实现、隔离测试、文档、正常commit/push；**不授权部署生产、修改生产配置/库、重启或停止服务、启用模型/外发资料、全库回填。** 不使用OpenCode。不递归删除/移动或改变权限。不能把本任务当作“部署后请Codex验收”。

流程固定为：开发提交固定commit及证据 → 接收Codex独立验收任务并配合验证 → Codex验收通过 → 用户明确授权该次生产发布commit与范围 → 发布者按授权执行 → 上线验证。开发者自测通过不能代替Codex验收；验收通过也不能代替用户发布授权。旧迁移授权已完成，不沿用。

## 仍需条件的后续验收，不伪装完成

- **A真实链路**：本地/隔离源使用合法合成PDF、扫描PDF、HTML、图片及坏文件，走来源索引→worker→发布→隔离同步；修改原文/重启/三连跑，验证新旧证据、人工区hash。生产“新增研报到Windows”的实测须在明确授权的验收/维护窗口进行；无授权时记NOT_RUN，不能自行往真实资料源注入测试文件。此次重提取历史资料不能替代新增来源版本入口验证。
- **B/C真实质量**：实现离线可验证，不以缺少真实模型授权为由留下执行器空壳。真实小批调用另需provider/资料范围/请求与token或金额上限的明确授权；提供预算预估、样本计划，未授权不调用。关键数字/结论必须能人工核对，mock不代表模型质量。
- **D真实应用**：先交背景包契约和保存/重放测试；若目标仓库/接口未明确，提交最小待确认信息，不擅自改其他项目或交易系统。应用联通/凭据/部署也需发布授权。
- **E运行保障**：提交一致性备份调度与恢复抽检、告警方案/隔离证据，生产定时任务启用另行授权；7天观察只累计真实时间。保留旧数据/旧证据，不引入自动清理。
- **API令牌维护**：本轮Codex工具输出疏漏的令牌轮换列为运维维护项；不打印旧值，不自动改生产；授权后同步更新消费者并验证旧令牌被拒绝。

## 开发交接及Codex验收任务 AC1

开发报告必须逐任务给出实现commit、RED/GREEN证据、运行命令、实际结果、未完成项；区分源码/离线/真实质量/生产部署四类状态。补齐预发布清单（镜像与源码标识、配置差异、备份/回退、上线验证计划），此时仍不执行部署。

提交后等待Codex独立执行AC1：固定源码SHA；全回归；Q01–Q05反例；fake provider的A→B→C三连跑、重启、同一事件幂等、人工编辑保留；D历史包时间与重放；核对外发开关关闭。交付者只能配合，不自行宣布独立验收通过。

AC1报告给出可发布的具体模块与未验收范围；用户据此授权具体发布。AC2上线检查只能在该次授权后执行。新缺陷按影响范围分流，P2不自动变成全项目发布门禁，但不得开启其影响且尚未验收的功能。
