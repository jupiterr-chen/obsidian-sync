## 问题及影响范围

### AC01 / P1：旧库升级未补summary_outbox字段

`app/knowledge/summaries.py:68–92`：SCHEMA先执行基于event_key的CREATE INDEX；旧summary_outbox没有该列。后续ALTER只照顾summaries，也没有给summary_outbox补字段。探针从Git `2a85fc5`读取真实旧SCHEMA建立隔离库，调用新ensure_schema直接失败；生产只读列清单与旧SCHEMA一致。

影响：不是空库测试问题，而是这次代码部署到现网后的升级路径。即使chat=None，worker也会进入consume_updates/ensure_schema并报错，周期后半段中断、last_ok=false；library和既有阅读不是由此自动停机。修复需前向幂等迁移、数据保留、旧版空/非空队列验证，不能重建/清空生产表来规避。

### AC02 / P1：B的分析内容未进入C；恢复窗口会重复生成

`summaries.py:152–203,265–329`只读取claims并拼接其statement；`analysis_tasks.py`完成后只更新analysis_tasks/analysis_runs/outbox，并未将正文或分析结果接入C的证据集合。首次公司报告通常没有人工claims。结果是已有完整提取且B生成成功，C仍拿到空证据，只把source/doc_id/version_id当更新原因发给模型，并持久化done。这不是模型质量差，而是输入材料为空。

主题路径也尚未完整：entities_for_document只映射symbol，公司以外返回空；_entity_claim_evidence对topic返回空。不要将“能手工插入topic事件”当作主题知识自动更新完成。接线可直接用带版本的分析结果/原文证据，不要求强行把模型结论写成人工accepted claim。

同模块的恢复问题为P2、合并修复：record_summary提交成功与outbox consumed分属两次事务；中间中断，重启后同event_key再次调用模型、追加revision。探针使用已接受且有原文引用的合成claim，排除了空证据因素，仍得到2次调用/2版。应复用已经落盘的结果；不要承诺远程服务响应未落盘时也能无条件做到恰一次。

### AC03 / P1（限完整单篇分析启用）：默认只分析前8块

`analysis_tasks.py:206–260`的retriever取get_blocks()前limit个，execute_analysis_run默认top_k=8；单篇执行器未覆盖该默认。100块合成研报仅一次调用，block99不在prompt，任务却done。页面显示“100个正文块”，没有给出实际只读8块的覆盖范围。报告后半的风险/反证/附表会被静默遗漏。

需要章节/分段处理与汇总，或预算不足时明确partial/待续、覆盖区间；不能把局部摘要作为完整分析。仅放宽一个固定top_k不足以处理真实长文。此项不阻止已有正文阅读。

配置接线同时明确状态：当前KnowledgeWorker和CLI调用run_cycle不传chat；代码没有读取analysis.enabled并组装provider/预算，只有Python函数注入接缝。因此正常服务不是配置好真实provider就会自动运行B/C。保留默认关闭是正确的，但要交付可离线验收的配置接线，或如实标为尚未实现，不能说只欠B4质量验收。未授权时绝不真实启用。

### AC04 / P2：分析发布状态与版本入口不完整

`analysis_publish.py:27,233`使用未导入的STATUS_FAILED，pending或failed任务进入索引分支时报NameError；超过单轮5项、预算阻塞或失败时都可能遇到。既有测试只覆盖blocked/done，没覆盖真正待处理队列。

`analysis_publish.py:31–37,196–198,218–228`文件身份只含source/doc_id/extraction_id，未含model/prompt/template/task_key。pv1与pv2在数据库是两个任务，文件却共用同一地址；write_candidate保护旧稿并产生候选是正确的，但发布器忽略实际写入路径，索引两行都指向pv1，pv2候选不可从新版本索引到达。需完整发布身份并保存实际落盘路径，保留旧版和人工修改。作为B发布模块小修一起完成，不阻断无关的阅读功能。

### AC05 / P2，D接口修复清单：无截止时间仍可能选到旧版

`background.py:135–154`不传as_of时仍按first_observed_at/synced_at/version_id排序，未按is_current选当前。首次整库接入时不同版本可能具有相同接入时间；反例a-current标为当前、z-old标为旧版，两时间相同，返回z-old。应把无截止时间的当前视图与历史可见版选择区分；同时间不可靠version_id字典序推断新旧。此项不否定Q01原历史过滤反例已修复；D尚未接入实际投资应用，列为D启用前小修，不阻断阅读。
