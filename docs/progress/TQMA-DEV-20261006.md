## TQ 交付（先行）

- **TQ1 源头路由**（`quality.py` v2，配置版本 2 → recipe 变更）：损伤指纹=C0 密度/连续运行、C1/DEL、CID 式高位 Latin 密集运行（≥3 段×6 字符或单段≥18）；**合法字符永不判伤**（¥ £ Ø Ë é 負號 均有回归保护，不删字符冒充修复）；高字符量≠健康；旧引擎单独**不**强制页 OCR（干净文本保留，引擎标记进 TQ0 清单，原生重提取是 TQ3 的解法）。逐页 CID 追踪（`cid_pages`）。
- **TQ2 OCR 选择与下游防护**：坏文本层 + 干净 OCR → **替换**不拼接（替换记录为诊断 issue）；健康稀疏层仍拼接；OCR 失败/低置信/超页限 → review + `damaged_text_layer` 显式标记，永不假 ready，坏文本保留可读供诊断。下游：`block_evidence_usable` 过滤总结证据、分析 prompt（执行器与检索缝双重）、默认检索索引（SELECTION_POLICY v2）；全文污染文档分析诚实 failed（no_usable_evidence）；阅读笔记逐页标"疑似污染勿当证据"，索引入口区分 正文可用/需修复（N 页）/review/未提取。
- **TQ0 清单**（`text_quality.py` + CLI `quality-inventory`）：五口径分开计数（文档/当前与历史版本/提取/页/文件）；引擎/recipe/issues/页分类（记录状态+新鲜扫描）/可用块比/原文在位/推荐动作（keep/原生重提取候选/OCR候选/缺原文/人工复核）；**旧 stdlib-pdf 无 degraded 标记也入选**；推荐是候选不是损坏判定；同库 manifest 哈希可复算；全程只读。
- **TQ3 有界重处理**（`repair.py` + CLI `reprocess --batch-id --dry-run`）：从清单显式选批（确定性排序、有界），按当前 recipe 注册为新 extraction 身份，走正常 job（租约=崩溃续跑）；三连跑注册一次；**坏新结果不覆盖旧入口**（入口=最新有可用文本的提取，坏结果标"暂用上一版正文"）；旧提取/blocks/证据 URL/旧笔记全保留；本周期新提取按 event_key 恰一次驱动实体总结事件。无隐式全库。
- **TQ4 治理 dry-run**（`governance.py` + CLI `governance-plan`）：manifest+实际 hash+发布引用的逐文件处置计划——当前入口 keep、机器被替代副本=档案候选（带 path/sha/owner 全身份）、人工编辑/未知归属=冲突必留；**计划不执行任何删除/移动**；执行需逐路径授权。
