- **SF01（S1 主题不扩大资料范围）**：`consume_updates`/`_summary_evidence`/`_entity_document_evidence` 增加 `allowed_documents`（(source,doc_id) 集合）；worker 只从**声明的 scope**（symbols+doc_ids）推导授权文档集——主题规则只增加"总结哪些实体"，绝不增加"发送哪些文档"；文档正文与派生分析（analysis 结果）同受文档级过滤；claims（系统自有已审研究记忆）不按文档过滤。哨兵反例：DENIED 文档正文不再进入任何主题总结的证据。
- **SF02（S2 新稿必须赢得入口）**：`effective_extraction` 改为两段式——优先**最新全可用**提取（≥1 块且每块证据可用）；部分损坏的较新提取不压完整健康旧稿；仅当无任何全可用提取时，以最新部分可用提取作**显式降级回退**。阅读/检索/治理共用；早前断言"混合新稿必须胜出"的测试已按需求修正（部分损坏→保旧入口；完整健康新稿→切换）。
- **SF03（S2 人工引用保护）**：治理扫描**生成目录之外的整个 Vault**——Obsidian wikilink（含路径前缀、`#^片段`锚、别名）、普通 markdown 链接，扩展名可选匹配；被任何人工笔记引用的文件无论机器归属一律 KEEP。
- **SF04（S3 执行层遵守冻结 recipe）**：`JobRunner.run_extract_jobs` 领取后校验 `job.config_digest == 运行时 recipe`；不符则**拒绝执行**——job 保持其租约（无热循环）、记录 `recipe_mismatch`（两个 digest 都写明）、可被批准 recipe 的 runner 或新批次恢复；绝不以错误 recipe 落提取。回归含"批准 runner 在租约到期后成功执行"的完整恢复路径。
