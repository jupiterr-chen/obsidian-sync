## 实现要点

- **R1**：`ensure_schema` 先检测/补列（summary_outbox.event_key、summaries.event_key）再执行含唯一索引的 SCHEMA；旧库（从 git `2a85fc5` 真实旧 SCHEMA 构建）升级幂等、数据保留、中断重试干净；旧库+模型关闭跑完整 worker 周期成功（评审指出的周期后半段中断路径）。
- **R2**：C 的证据 = claims + **文档自有正文块**（绑 source/version/extraction/block）+ **已完成单篇分析**（绑 task_key/run_id/模型身份）；prompt 与持久证据都含原文/分析文本。无证据 → blocked(insufficient_evidence) 消费事件，绝不付费生成空总结。主题映射为**最小可配置**（extra.summarization.topics 关键词规则），未配置则不产生主题实体，不声称自动主题发现。无关公司不更新。
- **R2b**：按 event_key 查找已落盘 DONE 修订——落盘后、消费前中断，重试复用结果（1 次调用、1 版）；网络响应未落盘的模糊失败如实保留 pending 并允许一次重试（docstring 明示，不假装零成本恰一次）。
- **R3 覆盖**：长文按连续 8 块分段，**每块都进 prompt**（100 块反例：block 99 到达模型）；多段再做一次合并调用；每段完成即持久化进度，崩溃/预算中止后**续跑不重付已完成段**（显式续跑测试：cap=3 → 3 段 partial → 恢复只付余下 2 段+合并）；预算不足为诚实 **partial**（任务行+run 的 coverage 记录总块/已覆盖/段数/合并待续；结果注记"部分覆盖…待续"），永不以截断冒充完成；不可重试失败如实 failed。
- **R3 服务接线**：`resolve_analysis_runtime` 从配置装配（`analysis.enabled` 默认关闭；真实 provider 还须 `egress_allowed=true`；离线 `scripted-chat` 为验证路径；错误 provider 类型**响亮报错**而非静默禁用）；CLI `worker --once` 与常驻 KnowledgeWorker 均经此入口；关闭时 0 调用（usage_events=0 断言）；vision 不得冒充 chat（R03 规则保持）。
